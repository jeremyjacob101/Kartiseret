The requests collectors use Python `requests` for both ordinary page HTML and the sites' public JSON/AJAX data routes. Calling a site's data API is still a Requests transport; the data source differs, not the HTTP client.

## What changed after the rerun

- Jerusalem's request collector now resolves relative event links to the same absolute URLs as Selenium. Its 45-day full output matched exactly after the fix.
- MovieLand showtimes now enriches missing catalog films from each schedule event's discovered movie ID and validates the film title before using its metadata. This fixed one catalog-coverage failure and produced an exact 517-row full pair. The 129-row divergence in another complete pair is still unexplained, so Requests is not the production default there.
- Rav-Hen now uses Requests first with Selenium fallback after the 269-row full pair matched exactly; earlier same-day comparisons also contained five later exact full pairs.
- Hot Cinema and Yes Planet showed transient same-day/source schedule differences across complete pairs. Each subsequently matched exactly in a full rerun, including a reversed execution order; both remain Requests-first with the existing full Selenium fallback.
- Tel Aviv matched exactly twice in the latest retest, but its Requests time was 73–81 seconds versus Selenium at 53–57 seconds. Earlier full pairs were much faster for Requests, so the route remains enabled but this run does not support a speedup claim.
- Cinema City coming-soon's repeated timeout occurs before detail scraping at the pagination wait. The complete-result guard remains in place; accepting the first 12 cards would produce partial data.
