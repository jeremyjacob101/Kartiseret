## Fixes found during release checks

- **Rav-Hen:** support the newly present French original-language code using the existing browser normalization (`French`); unknown languages still fail. Validate film-detail IDs against the requested film. Apply Yes Planet's existing non-screening-card guard to the Rav-Hen browser fallback: skip an untitled card only if it has no ticket links; reject unidentified bookable shows. A complete rerun matched **267/267** exactly.
- **Haifa:** use the page's explicit `Events.init.startDate` for pagination. The site can omit today's active slide once current-day events disappear while still listing future films. Missing initial-date evidence still fails; no date is guessed. A complete pair matched **46/46** exactly.
- **Tel Aviv:** preserve its legacy null titles when no English translation exists. This is an explicit source-specific exception to title validation, with ticket/date/location and all 60 calendar dates still required. The repeat matched **258/258** exactly, including those null fields.
- **Cinema City browser pagination:** wait for both the list and load-more button state to settle. The old loop could read the list while the final React batch was still arriving. The initial coming-soon pair had 47 exact shared rows and eight Requests-only films; independent browser inspection found all eight on the fully expanded listing and confirmed their metadata. The corrected browser collector now matches **55/55** exactly. The listing has 70 films; the same 15 legacy title-variant exclusions produce 55 output rows. A regression test simulates the button disappearing before the final cards arrive, and stalled pagination fails rather than returning the first page.
- **HTTP/session lifecycle:** reject HTTP errors and recognizable HTML/Cloudflare challenges even when status is 200. Keep the same connection pool when Wix enables POST retries after bootstrap, so the session still owns and closes its initial connections. Each collection uses an isolated session with bounded retries and explicit timeouts.
- **Fallback calendar:** refresh the source calendar for the new browser attempt after midnight while preserving the outer runner duration and weekday. A regression test covers December 31 to January 1.
- **Validation:** check discovered/completed coverage counts, equal column lengths, required dates/times/locations/ticket links, and required titles where the existing source contract requires them. Optional metadata and filtering remain unchanged. The read-only harness now invokes the same final Requests validator as production.

## Production fallback and publication

A successful validated HTTP attempt starts **zero Chrome instances**. A denial, timeout, malformed HTML/JSON, incomplete coverage or invalid required screening data fails that entire HTTP attempt. All partial rows, metadata buffers and empty-result evidence are discarded; one fresh Selenium collection gets a distinct snapshot identity. Diagnostics connect the fallback to the failed snapshot and error type.

Only the successful whole collection reaches the upload boundary. Upload, logging, lease and storage failures do not trigger another transport collection or duplicate upload. If both transports fail, neither snapshot can complete, so the existing publication protections preserve the prior published source. Main's outer retries and browser cleanup still apply. Runtime checks detect observable problems; they cannot guarantee detection of every future silent change in source data.
