Comparisons preserve duplicate rows and exact values and types, ignoring only generated run and snapshot IDs. ### MovieLand

In the Requests-first run, Requests returned 517 rows and Selenium 516. The only extra Requests row was Ali G at Glilot, 20:25 on November 2, captured after that showing time. In the reversed-order run both returned 516 rows exactly. Requests was much faster in both runs, but the mismatch means this does not meet the exact-parity gate; production remains on Selenium.

### Tel Aviv Cinematheque

All three complete pairs matched all 337 rows, including a reversed-order pair. Average per-collector time was 2.23s for Requests and 57.65s for Selenium, about 96% less collection time in this sample. This supports the existing Requests-first default. Earlier Requests runs were much slower, so this is a measured per-scraper result, not a guarantee for total pipeline time.

### Sam Spiegel Cinema

The restored scraper from `main` is enabled. Both complete comparisons matched all 30 schedule cards exactly. Requests averaged 1.52s; Selenium averaged 7.49s. The Requests collector reads the existing server-rendered bilingual HTML, so no browser is needed when that structure validates.

I also inspected the public WordPress REST routes. The movie catalog route returns film records and the events route returns unrelated event posts; neither exposes the complete screening schedule. The ordinary schedule HTML is the viable source, not a separate schedule API.

### Holon Cinematheque

Holon is enabled in the registry, and the scraper now reads the live calendar through the site's `get_events` AJAX endpoint, then visits each discovered event detail page. The full run covered five weeks, all 35 dates, 46 calendar activities, and 31 event pages, producing 45 rows. Selenium and Requests matched every row except one ticket URL: for the November 23 screening of קוֹמָטוֹגֶ'ן, Selenium returned the Smarticket URL with `?interface=12`; Requests returned the event page URL. Other fields and row keys matched.

Requests took 57.3s versus 131.7s for Selenium, but the remaining URL mismatch fails the exact-data requirement. Holon therefore remains Selenium-default. The Requests implementation is retained for follow-up, but it is not enabled as production transport. The scraper also skips an event only when its detail page has no ticket form and all matching calendar occurrences have already passed; a future event without details fails closed.
