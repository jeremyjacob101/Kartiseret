# Full scraper retest — 2026-11-04

This retest ran the complete collection path for every one of the 18 enabled scrapers, forcing Selenium and Requests independently where both implementations exist. The comparison preserves duplicate rows, values, and types; only generated run and snapshot IDs are ignored. Runs are read-only: no database writes, publication, notifications, or production timing-history updates.

Times include browser startup or HTTP session setup, discovery, metadata, schedules, parsing, validation, and cleanup. They are per-scraper times, not end-to-end scheduler savings. The latest branch includes `main` through `1f23c597` before these follow-up changes.

## Findings requiring follow-up

### MovieLand showtimes

Both full comparisons completed, but neither matched. Selenium returned 1,438 and then 1,342 rows; Requests returned 1,480 rows in both comparisons. The output differences were Requests-only and covered screenings across multiple dates and locations. The repeat confirms the mismatch is not a single transient row, so Requests stays disabled for this scraper.

### Hot Cinema showtimes

The original Requests collector trusted `MovieEventsDaysFilter`. The live endpoint returned different, incomplete date sets on successive calls, producing 894 missing Selenium rows in one comparison and one missing row in another. The collector now queries every calendar date for all 12 theaters from the frozen scrape date through the end of the following month. It verified all 696 theater/date combinations in these runs and detected days with events omitted by the filter.

Three complete pairs after that correction produced 3,508 vs 3,510 rows (two Requests-only “Not Just Cinema” events), then 3,508/3,508 twice. The corrected route was much faster, but the single complete mismatch fails the exact-parity requirement; the production default is therefore Selenium. The Requests route and coverage tests remain available for further investigation.

### Holon

The live page returned a LiteSpeed “403 Forbidden” page to both Requests and headless Chrome. Selenium consequently had no `.events-results .entry-result` element to read. This confirms a site access failure, not a selector change that can be safely patched from today’s output. The prior November 2 comparison had a separate one-field ticket URL mismatch (44/45 rows exact), so Requests remains unqualified as well.

### Cinema City coming soon

The full Selenium run started with 12 cards and later reached 65 before the “show me more films” action timed out waiting for another increase. A fresh diagnostic started at 12; after a 15-second wait the count was still 12, the button remained enabled, and there was no end-of-list marker. The page therefore behaves inconsistently, and treating a no-growth timeout as a complete catalog would be unsafe. No complete independent Requests route was established.

## Verification

- The independent full-output harness completed for all 18 scraper classes; MovieLand showtimes and Tel Aviv were repeated in reversed order, Sam Spiegel and Holon were repeated, and Hot Cinema had three additional complete paired comparisons after its coverage correction.
- The comparison artifacts preserve every complete output and mismatch. Raw HTTP response captures for the mismatching MovieLand, Hot Cinema, and Holon runs are in [`full-retest-2026-11-04.tar.gz`](evidence/full-retest-2026-11-04.tar.gz).
- The backend suite passed after the Hot Cinema correction and default change: **435 tests**.
- Full `npm run verify` passed on the final branch: lint, formatting, type checks, builds, SSR/browser/SEO smoke checks, **594 web tests**, **147 server tests**, **91 database integration tests passed (1 skipped)**, and **9 end-to-end tests**.
- Image-blocking experiments were not run. The normal scheduler/concurrency total was not benchmarked, so no total pipeline speedup is claimed.

The implementation has exact Requests parity for 13 production defaults. The five Selenium defaults preserve the current browser path. Two current site-level failures remain visible: Holon returns 403 to both transports, and Cinema City coming soon cannot complete its live pagination. Keep the PR draft until those failures are either corrected or explicitly accepted.
